NAME
     git-pr – create, update, inspect and fast-forward pull requests via AGit
     flow

SYNOPSIS
     git pr [remote] target-branch [-t title] [-d description] [-o topic] [-f]
         [-n]
     git pr --status [remote] [target]
     git pr --merge num [remote]
     git pr --list [remote]
     git pr -h

DESCRIPTION
     git-pr is a thin wrapper around git-push(1) that drives the AGit flow
     used by FreeBSD.  It pushes the current HEAD to the magic refspec
     refs/for/<target>/<topic> so that the server creates or updates a pull
     request in a single step.

     Beyond push, the tool exposes several read/write modes backed by the
     Forgejo REST API: --status to find pull requests whose head branch
     matches the current topic (robust to rebases), --list to enumerate all
     open pull requests, and --merge to fast-forward the target branch locally
     onto a pull request head.

     The topic branch defaults to the current branch.  If the current branch
     is named <target>/<topic> the <target>/ prefix is stripped automatically.

     When neither -t nor -d is supplied and standard input is a terminal, an
     editor is opened with a template pre-filled from the last commit message
     and the list of commits between target and HEAD, mirroring the workflow
     of git-commit(1).  The first line of the resulting message becomes the
     title and everything after the first blank line becomes the description.
     Lines starting with ‘#’ are ignored.

OPTIONS
     -t title        Set the pull request title and skip the editor.

     -d description  Set the pull request description.

     -o topic        Override the topic branch name.  Defaults to the current
                     branch with any leading <target>/ segment removed.

     -f              Allow force-push (emits -o force-push=true).  Required
                     when updating a pull request with a rewritten history
                     (e.g. after a rebase).

     -n              Dry-run.  Print the equivalent git-push(1) invocation
                     without executing it.

     -h, --help      Show usage and exit.

MODES
   --status [remote [target]]
     Query the Forgejo API at remote (default origin) for pull requests whose
     head.ref matches the current topic branch, either exactly or as a
     trailing /<topic> segment.  If target is given, the <target>/ prefix is
     stripped from the current branch before matching.

     Results include the pull request number, state, title, URL, head ref with
     short SHA, and base branch.  Because matching is done on branch name
     rather than commit identity, --status remains accurate after a local
     rebase.

     All pages of open and closed pull requests are scanned.  Requires curl(1)
     and jq(1).

   --list [remote]
     List every open pull request on remote (default origin).  For each pull
     request the number, title, author login, head branch, base branch and web
     URL are printed, sorted by number.  All pages are fetched.  Requires
     curl(1) and jq(1).

   --merge num [remote]
     Fast-forward the pull request's base branch locally onto the pull request
     head.  The pull request metadata is fetched from the API to resolve the
     base branch and expected head SHA.  The operation aborts if:
     •   the working tree has uncommitted changes,
     •   the pull request is not in the open state,
     •   the local base branch has diverged from the remote base branch, or
     •   the pull request head is not a descendant of the remote base (non
         fast-forwardable).

     On success, the local base branch is moved to the pull request head and
     the command prints the git-push(1) invocation needed to publish the
     change.  No push is performed automatically.

ENVIRONMENT
     GIT_EDITOR, VISUAL, EDITOR
                 Consulted in that order (via git var GIT_EDITOR) to pick the
                 editor used to compose the pull request message.  Falls back
                 to vi(1).

     FORGEJO_TOKEN
                 API token used by --status, --list and --merge when no
                 forgejo.token is set in git configuration.

CONFIGURATION
     Read via git-config(1) in the usual cascade (local then global then
     system).

     pr.remote      Default remote when none is given on the command line.
                    When set, the remote positional argument may be omitted,
                    allowing
                          git pr <target-branch>
                    and using pr.remote implicitly.  The same default is used
                    by --status, --list and --merge in place of origin.
                    Typically set per repository:

                          git config pr.remote upstream

     forgejo.token  API token used by the API-backed modes.  Takes precedence
                    over FORGEJO_TOKEN.  Typically set with:

                          git config --global forgejo.token <your-token>

EXIT STATUS
     The git-pr utility exits 0 on success, and >0 if an error occurs.  A non-
     zero status is returned when arguments are invalid, when the working tree
     is dirty during --merge, when a fast-forward is not possible, when the
     API returns a non-200 response, or when an underlying git(1) command
     fails.

EXAMPLES
     Open a pull request against origin/main, composing the message in an
     editor:

           git pr origin main

     Create a pull request non-interactively:

           git pr origin main -t "Fix login bug" -d "Closes #42"

     Update an existing pull request after a local rebase:

           git pr origin main -f

     Preview the push without executing it:

           git pr origin main -n

     Check whether the current topic branch is already associated with a pull
     request:

           git pr --status

     List every open pull request on origin:

           git pr --list

     Fast-forward the target branch of PR #123 locally and publish it:

           git pr --merge 123
           git push origin main
