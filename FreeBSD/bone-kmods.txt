NAME
     ng_pcap – packet capturing netgraph node type

SYNOPSIS
     #include <netgraph/ng_pcap.h>

DESCRIPTION
     The pcap node type accepts NG_PCAP_MAX_LINKS source connections and one
     snoop connection to receive all the packet captures.  All source
     connections must be configured to be one of:
     •   ether
     •   inet
     •   inet6
     ng_pcap adds the appropriate pcap(3) header based on the link
     configuration.  For ether all 802.1q VLAN tags will be placed inline.
     For inet and inet6 fake ethernet headers will be created.  This allows
     both layer 2 and layer 3 data to be combined.

     The snoop link is meant to be connected to an ng_socket(4) and can be
     used with nghook(8).  The default snaplen is set to match nghook(8) and
     is smaller than both the default and maximum size of tcpdump(1) but may
     be configured larger (although nghook(8) has no way to handle larger
     sizes).

HOOKS
     This node type supports the following hooks:

     snoop
          This is the link that receives all the PCAP data including an
          initial PCAP file header.  It discards any data you send it.  Once
          this is connected you can't change the configuration.

     source<n>
          Where n is in the range [0, NG_PCAP_MAX_LINKS) can be connected.
          Each will need to be configured before PCAP data is sent on to
          snoop.

CONTROL MESSAGES
     This node type supports the generic control messages, plus the following:

     NGM_PCAP_GET_CONFIG (getconfig)
          Returns the current configuration as a struct ng_pcap_config.

     NGM_PCAP_SET_CONFIG (setconfig)
          Set the node configuration.  This command takes a struct
          ng_pcap_config as an argument:

          /* Node configuration structure */
          struct ng_pcap_config {
                  uint8_t         persistent;
                  int32_t         snaplen;
          };

          If persistent is not the default of 0, the node will not
          automatically shutdown when the snoop link is disconnected.  snaplen
          determines how much of each packet is captured as it does for
          tcpdump(1).  This includes any fake headers that may be added.  The
          default is set to the best value for nghook(8).  The minimimum
          allowed is NG_PACP_MIN_SNAPLEN and the maximum is
          NG_PACP_MAX_SNAPLEN.

     NGM_PCAP_GET_SOURCE_TYPE (getsourcetype)
          This command takes a ng_parse_hookbuf_type, which is the name of one
          of the source hooks, e.g.: source0.  It returns a fixed length
          string of NG_PCAP_PKT_TYPE_LENGTH indicating how it is currently
          treating packets.  This will be one of:

          HOOK_PKT_UNSET (none)
               The default value for new source links.  You can also set any
               link to this to stop capturing packets temporarily.

          HOOK_PKT_ETHER (ether)
               You should set any link that is passing layer 2 traffic to
               this.

          HOOK_PKT_INET (inet)
               Provided you compiled with INET defined, you can set any link
               passing TCP/IP packets to this value.  This will add a fake
               ethernet frame to the packet and does count against your
               snaplen.

          HOOK_PKT_INET6 (inet6)
               Provided you compiled with INET6 defined, you can set any link
               passing TCP/IP version 6 packets to this value.  This will add
               a fake ethernet frame to the packet and does count against your
               snaplen.

     NGM_PCAP_SET_SOURCE_TYPE (setsourcetype)
          Unlike configuration which can not be changed after snoop is
          connected, you can change a source type at any time.  This is useful
          for temporarily disabling a pcap source link.  This command takes a
          struct ng_pcap_set_source_type as an argument:

          /* source configuration structure */
          struct ng_pcap_config {
                  char    hook[NG_HOOKSIZ];
                  char    type[NG_PCAP_PKT_TYPE_LENGTH];
          };

          hook is the name of the source link you want to set.  type is one of
          the strings returned by NGM_PCAP_GET_SOURCE_TYPE above.

EXAMPLES
     The minimum example is not very useful but it does show how to put all
     the pieces togehter.  For this we will use an ng_tee(4), which is almost
     always what you want with ng_pcap, and an ng_iface(4).  This example
     creates this configuration:


                          right2left ---+  +--------------------+
                                        |  | left2right         | source0
             +----------+            +--+--+--+            +----+----+
             | ng_iface |            | ng_tee |            | ng_pcap |
             | foo0     |            | tee0   |            | pcap0   |
             +----+-----+            +--+--+--+            +---------+
                  | source0        left |  |
                  +---------------------+  +--- right


     The interface is not connected to anything but that won't prevent us from
     using it to capture packets.

         #!/bin/sh

         ngctl -f- << EOF
         mkpeer .: iface i inet
         name .:i foo0
         disconnect .: i
         mkpeer foo0: tee inet left
         name foo0:inet tee0
         mkpeer tee0: pcap left2right source0
         name tee0:left2right pcap0
         msg pcap0: setconfig { persistent=1 snaplen=1500 }
         msg pcap0: setsourcetype { hook="source0" type="inet" }
         EOF

     Before using you need to configure the interface.

         #!/bin/sh

         ifn=$(ngctl msg foo0: getifname | tail -1 | cut -d\" -f2)
         ifconfig $ifn name foo0
         ifconfig foo0 inet 192.168.128.1 192.168.128.2 up

     Finally we can use nghook(8) along with tcpdump(1) to test our pcap0:

         #!/bin/sh

         nghook -n pcap0: snoop | /usr/sbin/tcpdump -r -

     you will of course need to issue a ping to see traffic:

         #!/bin/sh

         ping 192.168.128.2

SHUTDOWN
     This node shuts down upon receipt of a NGM_SHUTDOWN control message.  If
     not configured to persist, the default, it also shuts down when the snoop
     link is removed.
